| 术语 | 含义 |

## 1. 产品定位与设计原则

### 1.1 一句话定位
**一站式、跨平台的家庭媒体中枢**——把用户自有的多种数据源（NAS / 媒体服务器 / 下载器 / PT 站 / 字幕站 / 追踪服务）整合进一个客户端，在手机、平板、桌面、电视、车机上以统一现代的体验访问家里的所有媒体资源。

### 1.2 核心差异化（设计时要让它"被看见"）
1. **不绑定品牌、用户自带数据源**：同一个 App 里可以同时挂群晖 + Plex + qBittorrent + 任意 PT 站。设计要能优雅地表达"多源并存"和"在不同源之间切换/聚合"。
2. **端到端串联是灵魂**：在视频详情页可以一键"找资源（PT）→ 发送下载器 → 自动入库 → 播放"。这条链是产品的招牌，设计上应让它顺滑、可追踪、有掌控感。
3. **媒体类型全覆盖**：视频、音乐（含无损/DSD）、漫画、电子书、笔记、照片，每一类都有"浏览 + 消费 + 管理"三层。
4. **专业级播放体验**：字幕（含 AI 翻译）、多音轨、转码、投屏、HDR/杜比、桌面歌词、车载、灵动岛……硬核功能多，但要对小白友好。

### 1.3 目标用户画像
- **核心用户**：有 NAS / 家庭媒体库的中高级玩家，追求"自己的资源、自己掌控"。
- **泛化用户**：被核心用户安利、只想"在沙发上看家里的电影、在通勤路上听家里的无损"的家庭成员（重消费、轻管理）。
- 设计含义：**管理类功能（连接、下载、刮削、去重）要强但可收纳；消费类功能（看、听、读）要轻且即开即用**。不同设备形态对这两类的侧重不同（见第 2、7 章）。

### 1.4 设计原则（建议，可被更好的理念替代）
- **消费优先**：打开即能看/听，配置不挡路。第一次没有任何源时，引导清晰、低门槛。
- **一致的"卡片 + 详情 + 播放/阅读器"三段式**：六大媒体类型尽量复用同一种心智模型，降低学习成本（但视觉可各有性格）。
- **进度可见、状态可控**：下载、刮削、转码、同步、人脸扫描等长任务都要有全局可见的进度与可中断入口。
- **跨端连续**：在手机上看到一半，回家用 TV/桌面接着看；正在听的歌切到车机继续。
- **专业不等于复杂**：把"高级选项"折叠在"刚刚好够用"的默认之后。

## 2. 平台矩阵与设备形态

产品需要覆盖 **5 大形态 / 7 个平台**，外加 2 个系统级延伸界面。设计需要"一套设计语言，四种落地形态"。

| 形态 | 平台 | 输入方式 | 观看距离 | 典型场景 | 功能侧重 |
|---|---|---|---|---|---|
| **手机** | iOS / Android | 触摸、竖屏为主 | ~30cm | 通勤听歌、床上看剧、随手管理 | 消费 + 轻管理，单手可达 |
| **平板** | iPadOS / Android | 触摸、横竖屏 | ~40cm | 沙发追剧、看漫画/书 | 消费为主，可双栏 |
| **桌面** | Windows / macOS / Linux | 鼠标 + 键盘、右键、快捷键、多窗口 | ~60cm | 整理媒体库、批量刮削、下载管理 | **管理最重**，信息密度高 |
| **TV（新增）** | Android TV / Apple TV(tvOS) / 大屏投影 | 遥控器 D-pad、语音、焦点导航 | 2–3m | 客厅观影、家庭共享 | **纯消费**，10 英尺体验 |
| **车载** | CarPlay / Android Auto | 旋钮/触摸、语音、强约束 | ~50cm | 开车听音乐/播客 | 仅音频浏览与播放，安全第一 |
| 系统延伸 | 锁屏 / 灵动岛 / Now Playing / 桌面歌词 / 桌面小组件 / 通知 | 系统原生 | — | 后台播放控制 | 见 §7.6 |

> **重要现状说明**
> - 现有代码已覆盖：手机、平板、桌面（含响应式 master-detail、玻璃风格）、CarPlay/Android Auto 音乐浏览、各类系统级集成。
> - **TV 端目前没有任何专门代码**——Android TV 只是复用了手机布局。**本次重新设计需要把 TV 当作一个全新的一等形态来规划**（第 7.4 节给出完整建议）。
> - 当前界面语言只有**中文、英文**两种（内容翻译另支持日/韩/法/德/西/俄等，见 §4.6）。

### 2.1 响应式断点（现状参考，可重新定义）
当前桌面/移动判断基于宽度断点：紧凑 <600 / 中等 600–840 / 展开 840–1200 / 大 1200–1600 / 超大 ≥1600；并区分"窗口内容排版（按宽度）"与"外壳形态（按平台）"。设计师可沿用，也可提出自己的断点体系——只要保证同一份内容在不同宽度下都成立。

## 3. 全局信息架构与导航

### 3.1 一级功能域（7 个）
产品由 7 个一级功能域构成。前 5 个是"内容域"，后 2 个是"工具域"。

| # | 功能域 | 职责 | 在导航中的可见性建议 |
|---|---|---|---|
| 1 | **影视** | 电影 / 剧集浏览、详情、播放、刮削、投屏、PT 联动 | 所有形态一级入口 |
| 2 | **音乐** | 曲库浏览、播放器、歌词、刮削、车载、桌面歌词 | 所有形态一级入口 |
| 3 | **相册** | 照片时间线、查看器、人脸/人物、去重 | 手机/平板/桌面/TV 一级入口 |
| 4 | **阅读** | 书籍 + 漫画 + 笔记（三合一） | 手机/平板/桌面一级入口；TV 弱化 |
| 5 | **我的** | 个人中心、设置、关于、账号 | 所有形态一级入口 |
| 6 | **传输 / 下载** | 上传/下载任务、下载器、PT 站、媒体管理 | 桌面一级入口；手机收纳进"我的"；TV 隐藏 |
| 7 | **连接源** | 数据源的添加/编辑/状态/发现 | 桌面一级入口；手机收纳进"我的"；TV 仅"选择已连接的源" |

> 现状：路由层是一个 8 分支外壳（影视/音乐/相册/阅读/我的 + 下载/传输/连接）。手机端底部只露 5 个内容/我的入口，后 3 个工具入口收纳在"我的"里；桌面端侧边栏把工具入口也展开。**这套取舍逻辑值得保留，但导航的形态、分组、命名完全可重做。**

### 3.2 跨端导航形态（建议，非强制）
- **手机**：底部 Tab（5 项）+ "我的"内的工具入口。详情页/播放器进入时底部栏隐藏。
- **平板/桌面**：侧边导航栏（图标，宽屏时展开文字）。"我的"用左右双栏（左分类、右详情）。支持键盘快捷键切 Tab、Esc 返回。
- **TV**：顶部或左侧大焦点导航，遥控器 D-pad 切换；首页以"继续观看 / 推荐 / 媒体库"横向 Rail 为主（详见 §7.4）。
- **车载**：系统模板化导航，只暴露音乐浏览树（专辑/艺人/歌单/最近）。

### 3.3 全局常驻元素（跨所有内容域）
这些元素无论在哪个功能域都可能出现，设计时要统一规划它们的"落点"：

1. **迷你播放器（音乐）**：常驻底部/边缘，显示封面+标题+播放控制，可上滑/点击展开全屏播放器，可跨域跟随用户。
2. **全局搜索**：能跨"当前域"检索；理想状态可做"全局聚合搜索"（一个搜索框查所有媒体类型 + 在线源）。
3. **后台长任务指示**：刮削进度、下载进度、上传进度、同步状态、人脸扫描进度——需要一个统一可见的入口（如顶部细进度条 / 任务中心）。
4. **连接状态**：当前活跃源、在线/离线/连接中，以及"切换源"的快捷入口。
5. **投屏状态**：正在投屏时的常驻控制条。
6. **Toast / 通知**：统一的轻提示层。

### 3.4 各模块在不同平台的取舍
| 模块 | 手机 | 平板 | 桌面 | TV | 车载 |
|---|---|---|---|---|---|
| 影视消费（看） | ✅ | ✅ | ✅ | ✅ 主角 | — |

## 4. 核心横切系统（所有模块共享）

这一章是"地基"。第 5 章每个模块都建立在这些系统之上。设计这些系统时要意识到它们会在很多地方被复用。

### 4.1 数据源与连接中心 ⭐（产品根基）

这是整个产品的入口与命脉。所有内容都来自"源"。

#### 4.1.1 数据源全类型
| 分类 | 类型 | 用户需要填写 | 认证方式 |
|---|---|---|---|
| **NAS 设备** | 群晖 Synology | 地址、端口(默认5001)、账号、密码、SSL、QuickConnectID | 账号密码 + **二次验证(TOTP)** + "记住此设备" |
| | 威联通 QNAP | 地址、端口(8080)、账号、密码、SSL | 账号密码 |
| | 绿联 UGOS | 地址、端口、账号、密码 | 账号密码 + RSA 加密登录 |
| | 飞牛 fnOS | 地址、端口、账号、密码 | 账号密码 |
| **通用协议** | WebDAV | 地址、端口、账号、密码、SSL、基础路径 | 账号密码 |
| | SMB / CIFS | 地址、共享名、账号、密码 | 账号密码 |
| | FTP | 地址、端口(21)、账号、密码、加密(无/FTPS/FTPES)、路径 | 账号密码 + TLS |
| | SFTP | 地址、端口(22)、账号、密码或私钥、路径 | 账号密码 / SSH 私钥 |
| | UPnP/DLNA | （局域网自动发现，名称可选） | 无 |
| | 本地存储 | 本地文件夹路径 | 无 |
| **媒体服务器** | Jellyfin | 地址、端口(8096) | 账号密码 / API Key / **Quick Connect(PIN 授权)** |
| | Emby | 地址、端口(8096) | 账号密码 / API Key |
| | Plex | 地址、端口(32400) | **PIN 授权(plex.tv/link)** / 手动 Token |
| **下载器** | qBittorrent | 地址、端口(8080) | 账号密码 / API Key(v5.2+) |
| | Transmission | 地址、端口(9091)、RPC 路径 | 账号密码（可选） |
| | Aria2 | 地址、端口(6800) | RPC Secret（可选） |
| **媒体管理** | NASTool | 地址、端口(3000) | 账号密码 / API Token |
| | MoviePilot | 地址、端口(3001) | API Token |
| **追踪** | Trakt | — | **OAuth 设备码授权** |
| **PT 站** | 通用 PT 站点 | 站点地址、规则 | Cookie / 自定义请求头（如 x-api-key + authorization） |
| **字幕站** | OpenSubtitles | — | 账号密码 + API Key（均可选） |

#### 4.1.2 连接中心需要承载的交互
- **源列表**：按分类分组（存储 / 媒体库 / 下载器 / 管理 / 追踪 / PT / 字幕），每条显示名称、类型图标、**实时状态（在线 / 离线 / 连接中 / 需二次验证 / 错误）**，可重排序、设默认。
- **添加源**：选择类型 → 动态表单（字段随类型变化，含文本/密码/数字/开关/下拉/键值对列表）→ 实时校验 → **测试连接（成功/失败/需 2FA 的即时反馈）** → 保存并连接。
- **特殊认证流**（设计上要专门画）：
  - 群晖二次验证：弹出 OTP 输入 + "记住此设备"。
  - Jellyfin Quick Connect：展示 PIN，提示用户去服务端授权，App 轮询确认。
  - Plex PIN：展示 PIN + 引导去 plex.tv/link，轮询确认。
  - Trakt 设备码：展示设备码 + 引导去 trakt.tv 输入。
- **编辑 / 删除**：编辑时密码"留空即不变"；删除前确认并断开连接。
- **局域网自动发现**：扫描按钮 → 列出发现的设备（型号/版本）→ 点击预填表单。
- **凭据安全**：所有密码/令牌存系统钥匙串（Keychain/加密存储），用户视角是"凭据被安全保存"。

#### 4.1.3 源能力矩阵（决定一个源出现在哪些模块里）
| 源类型 | 文件浏览 | 视频库 | 音乐库 | 照片 | 下载任务 | 资源搜索 | 进度同步 |
|---|:--:|:--:|:--:|:--:|:--:|:--:|:--:|
| NAS / 通用协议 / 本地 | ✅ | ✅(扫描) | ✅(扫描) | ✅ | — | — | 本地 |
| Jellyfin/Emby/Plex | 只读虚拟 | ✅ | ✅ | ✅ | — | — | ✅ 服务端 |
| qB/Transmission/Aria2 | — | — | — | — | ✅ | — | — |
| NASTool/MoviePilot | — | — | — | — | 间接 | ✅ | — |
| Trakt | — | — | — | — | — | — | ✅ 观看记录 |
| PT 站 | — | — | — | — | — | ✅ 种子 | — |
| OpenSubtitles | — | — | — | — | — | ✅ 字幕 | — |

> 设计含义：**同一个内容模块（如"影视"）会聚合多个源的内容**（多个媒体库、多个 NAS 扫描目录）。设计要解决"多源如何聚合展示、如何按源筛选、如何切换源"。

### 4.2 账号与授权系统（会员分级）

产品有一套自有的账号/授权体系（与"连接数据源"是两回事——这是"使用本 App 的权限"）。

- **激活方式**：在线登录（账号密码 / 第三方 OAuth）或离线激活（邮箱 + 激活码 `XXXX-XXXX-XXXX`，本地 RSA 证书校验，7 天宽限期）。
- **等级体系**：

| 等级 | 获取 | 设备数 | 标识 | 解锁能力 |
|---|---|---|---|---|
| FREE | 默认 | 1 | 灰色 | 文件浏览、各类播放/阅读基础 |
| VIP | 激活码 | 3–5 | 金星 | TMDB 刮削、云同步、进度/收藏同步、无限源 |
| SVIP | 升级码 | 5–10 | 紫冠 | PT 站、媒体管理、高级下载器、Trakt |
| ADMIN | 特殊码 | ∞ | 红盾 | 后台、生成激活码 |

- **设备绑定**：超出设备上限时 FIFO 淘汰最早设备，被淘汰设备下次启动提示。
- **功能守卫（Feature Guard）**：未达等级的功能显示"需升级"占位，而非直接隐藏。

> 设计含义：需要设计**登录/激活页、设备管理页、会员等级标识、功能锁定占位、升级引导**。等级标识要在"我的"头部和被锁功能处一致出现。

### 4.3 跨端数据同步

通过用户自配的 **WebDAV** 做跨设备增量同步（快照哈希对比）。

- **可同步的数据**：播放进度、收藏、已看/历史、应用配置（主题+配色）、音乐设置。每类可单独开关。
- **触发**：手动"立即同步" + 后台自动。
- **冲突策略**：按时间戳"后写胜出"。
- **状态反馈**：同步报告（已拉取/已推送/失败）。

> 设计含义：需要"云同步设置页"（配置 WebDAV + 勾选同步项 + 立即同步 + 上次同步状态）。同步状态也应在全局可感知。

### 4.4 安全与隐私（应用锁）

- **PIN 码**：4–6 位，设置时二次确认。
- **生物识别**：Face ID / Touch ID / 指纹，可与 PIN 共存（生物失败降级 PIN）。
- **自动锁定时机**：立即 / 1 分钟 / 5 分钟 / 15 分钟 / 仅退出时。
- **应用切换器遮蔽**：后台预览图被遮挡。
- 解锁页、设置流程都需设计。

### 4.5 主题与外观系统

- **主题模式**：浅色 / 深色 / 跟随系统。
- **配色方案**：多套预设主色（可网格选择），评分色随分值变化（高分绿、中橙、低红）。
- **UI 风格**：现有两套——`Classic`（不透明 Material）与 `Glass`（iOS 26 风格液态玻璃，按明暗调模糊强度）。设计师可以**保留双风格、合并为一套、或提出全新的视觉语言**——这是设计自由度最大的地方之一。
- 玻璃/模糊在不同平台用不同实现（iOS/macOS 原生、其它平台 BackdropFilter、Web 关闭），设计时注意"玻璃效果不是所有平台都同样可得"。

### 4.6 国际化与内容语言

- **界面语言**：现支持中文、英文（架构支持扩展更多）。
- **内容语言偏好**：分三个维度独立设置——元数据语言、音频语言、字幕语言。
- **内容翻译目标语言**：zh-CN / zh-TW / en / ja / ko / fr / de / es / ru（用于字幕翻译、歌词翻译）。

### 4.7 AI 与智能能力

| 能力 | 用途 | 触发点 |
|---|---|---|
| **AI 字幕翻译** | 把当前字幕轨实时翻译为目标语言（优先翻译播放位置附近的段），结果落盘缓存 | 视频播放器字幕菜单 |
| **歌词翻译** | 歌词译文显示 | 音乐播放器 / 桌面歌词 |
| **人脸识别 + 人物聚合** | 扫描照片库，检测人脸→提取特征→聚类成"人物"，可重命名/合并 | 相册"人物"页 |
| **听声识曲（音纹）** | Chromaprint + AcoustID 指纹识别歌曲（降级为按标题搜索） | 音乐刮削 |

> 设计含义：这些都是**长耗时后台任务**，需要进度反馈、可中断、结果可确认。翻译有"翻译中/已缓存"状态；人脸有"扫描进度+聚类结果待确认"。

### 4.8 通知、后台与长任务

- **后台播放**：音乐/视频音频后台播放，锁屏与系统媒体控制。
- **后台扫描**：媒体库刮削、人脸识别可在后台进行（移动端有后台任务约束）。
- **完成通知**：下载/上传/转码完成可发系统通知。
- 全局应有"任务中心"概念，聚合下载、上传、刮削、同步、人脸扫描等长任务的进度。

### 5.1 影视 🎬（最大、最核心的模块）

#### 能力清单
- 媒体库浏览：全部 / 电影 / 剧集 / 其他 / 最近添加；网格/列表/海报墙切换。
- 首页编排：每日推荐 Hero、最近添加、电影库、剧集库（按剧分组）、电影系列合集、其他视频。
- 搜索（标题/原名/演员/导演）、排序（年份/评分/添加时间/标题）、按分类与媒体库/源筛选。
- 详情页：海报+背景图、简介、多源评分（TMDB/豆瓣/IMDb/Trakt）、演职员、季/集列表、相似推荐、多版本（不同清晰度）。
- 播放器：播放控制、倍速 0.5–4x、手势（进度/亮度/音量）、双击快进退、画中画、全屏/旋屏、书签、播放队列、自动下一集。
- 字幕：内嵌/外挂多格式、在线搜索下载（OpenSubtitles）、样式自定义、延迟调节、**AI 翻译**。
- 音轨/画质/转码：多音轨切换、清晰度选择（原始/480/720/1080/2K/4K）、服务端 + 客户端转码（CPU/MediaCodec/VideoToolbox）、HDR/杜比视界、音频直通。
- 投屏：AirPlay / DLNA / Chromecast，含进度同步、音量、字幕扩展。
- 刮削：TMDB/豆瓣/NFO，自动 + 手动 + 季级补全；边扫边显进度。
- 媒体服务器联动：继续观看、下一集、进度同步、标记已看、收藏。
- **PT 联动**：详情页/推荐项一键跳 PT 搜索（带年份）。
- 直播（M3U/EPG）。
- 重复视频检测。

#### 主要页面
1. **影视首页**：分区滚动（Hero + 多个横向 Rail + 库网格）。三阶段渐进加载（先统计、再首屏、最后全量）。顶部有全局刮削进度条。
2. **媒体库浏览页**：分 Tab（全部/电影/剧集/其他/最近），网格/列表切换，筛选/排序/搜索，多源/多库切换。
3. **视频详情页**：手机端 Hero+滚动内容；桌面端左侧固定信息栏 + 右侧滚动（master-detail）。包含播放/收藏/已看/刮削/PT 搜索/质量选择等动作，季集选择器，演职员，推荐 Rail。
4. **播放器页**：顶栏（返回/标题/书签/倍速）、中部（上一集/快退/播放暂停/快进/下一集）、底部进度条（缓冲/时间提示）、手势层、各类弹层（字幕选择、字幕样式、字幕下载、清晰度、音轨、宽高比、播放列表、书签、投屏设备）。
5. **手动刮削流程页**：搜索→候选列表→预览确认→保存。
6. **直播频道页 / 直播播放页**。

#### 关键交互（必须成立的）
- **字幕菜单**：一个入口聚合"选择字幕（内嵌/外挂/翻译轨）+ 在线下载 + 样式设置 + AI 翻译 + 关闭"。翻译进行时显示进度，可随时换目标语言。
- **清晰度切换**：选低清晰度或不兼容格式时触发转码，显示"转码中"与进度；失败回退原始。
- **投屏中**：界面切换为"投屏控制态"（设备名、播放控制、音量、字幕、断开）。
- **续看**：打开有历史的视频，提示"从 xx:xx 继续 / 重新开始"。
- **自动下一集**：播完自动进入队列下一集（可关）。

#### 状态
加载/骨架、扫描中（x/总数）、缓冲、转码中、无字幕、错误（可重试）、投屏中、无源引导。

#### 跨模块联动
- **影视 → PT 站 → 下载器 → 媒体管理 → 影视库 → 播放**（见 §6.1，招牌链路）。
- **影视 ↔ 媒体服务器**：进度/已看/收藏双向同步。
- **影视 ↔ Trakt**：播放完成上报观看记录。
- **影视 ↔ 字幕站**：在线字幕检索下载。
- **影视 ↔ 文件浏览器**：文件浏览器里点视频直接进播放器。

### 5.2 音乐 🎵

#### 能力清单
- 曲库浏览维度：歌曲 / 专辑 / 艺人 / 流派 / 年代 / 文件夹 / 歌单；封面墙、最近播放、统计。

#### 主要页面
1. **音乐首页**：Hero + 快捷卡片 + 分类入口（专辑/艺人/…）+ 最近播放墙 + 统计。
2. **曲库列表页**：维度 Tab、搜索/排序/筛选、列表/网格、分组、批量操作。
3. **全屏播放器**：信息态 ↔ 歌词态切换；旋转封面/Hero 过渡；进度、控制、模式、音量、队列入口。
4. **歌单详情页**、**音乐刮削页**（搜索→源→结果→预览→应用）、**音效/统计/重复/回收站/Scrobble/播放器设置** 等设置页。
5. **桌面歌词窗口**（独立悬浮窗）。

#### 关键交互
- **刮削确认**：识别结果要可预览（封面/歌词/标签）并由用户确认后再写入；批量时进队列、可看进度。
- **商业刮削源**：启用前展示合规风险提示。
- **歌词态**：自动滚动 + 卡拉 OK 高亮；手动滚动时暂停自动跟随；可调字号/偏移/译文。
- **桌面歌词**：开关、锁定/穿透、字体/颜色、偏移；窗口可拖动。

#### 状态
缓冲、无歌词、无封面、刮削中、识曲降级（指纹不可用→按名搜索）。

#### 跨模块联动
- **音乐 ↔ 文件浏览器**：文件里点音频进音乐播放。
- **音乐 ↔ 车载/系统**：跨形态接力播放（§7.6）。
- **音乐 ↔ 同步**：播放设置/统计可同步。

### 5.4 阅读 📚📖📝（书籍 + 漫画 + 笔记三合一）

#### 5.4.1 书籍
- **书架**：网格/封面墙、阅读进度、分类（全部/本机/NAS/在线）、搜索排序、最近阅读。
- **格式**：EPUB / PDF / MOBI / AZW3 / TXT / HTML。
- **阅读器**：翻页方式（滚动/滑动/仿真/覆盖/无）、字体/字号(12–32)/行距/段距/页边距、主题（日/护眼黄/护眼绿/夜/纯黑）、目录导航、书签、进度百分比、点按区域控制、音量键翻页、常亮。
- **TTS 朗读**：本地 + 在线（多音色）、语速 0.5–2x、音量、上一段/下一段、字符级高亮跟随、后台朗读。
- **在线书源（Legado 兼容）**：导入书源（JSON/URL）、规则解析（XPath/JSONPath/CSS/正则/JS）、跨源在线搜索（流式聚合去重）、章节目录、在线阅读 + 章节缓存离线。**应用不内置任何书源，用户自行导入**。

#### 5.4.2 漫画
- **书架**：网格、封面、页数、修改时间。
- **格式**：文件夹 / CBZ / CBR / CB7 / ZIP / RAR / 7Z / PDF。
- **阅读器**：模式（单页/双页/长条 Webtoon）、方向（左→右/右→左/垂直）、缩放（适宽/适高/适屏/原始）、背景色、长条间距、点按/双击/音量键翻页、预加载、进度恢复。

#### 5.4.3 笔记
- Markdown 渲染（任务列表/代码块/表格/图片/链接）。
- 树形目录浏览（文件夹展开/折叠、文件选中）。
- 搜索（文件名/全文/标签）。
- 编辑（编辑/预览/实时预览切换、保存回 NAS、自动保存）。
- 任务管理（待办状态、优先级、完成统计）。

#### 主要页面
**阅读首页（书/漫画/笔记三 Tab）**、各自**书架/列表页**、**电子书阅读器**、**漫画阅读器**、**在线书源搜索页 + 书源管理页**、**笔记浏览/编辑页（树 + 内容）**。

#### 关键交互
- 阅读器设置面板统一（字体/主题/翻页/亮度）。
- 在线书源：导入→搜索→加入书架→自动下载入本地。
- 笔记：桌面端可侧栏树 + 右侧编辑分屏；移动端弹出编辑。

#### 跨模块联动
- 书/漫画/笔记文件均来自文件源；文件浏览器点击对应文件进对应阅读器；阅读进度可跨端同步。

### 5.6 传输与下载生态 ⏬（招牌链路的中段）

包含 5 个子系统，是"找资源→下载→入库→播放"的中枢。

#### 5.6.1 传输任务（本机上传/下载/缓存）
- 三类任务：上传 / 下载 / 缓存（离线可播）。
- 状态机：等待→排队→传输中→(暂停↔传输)→完成/失败/取消。
- 并发管理（默认 3 并发）、进度、重试、清除已完成、完成通知。
- 缓存管理：按媒体类型限额、查看/删除。

#### 5.6.2 下载器（qB / Transmission / Aria2）
- 任务列表（名称/大小/进度/速度/做种下载数/状态）、按状态筛选、排序。
- 单任务控制：暂停/开始/删除/优先级/限速；批量控制。
- 添加任务：磁力 / 种子文件 / URL；自定义下载目录；可"暂停态添加"。
- 多下载器切换。

#### 5.6.3 PT 站
- 站点列表 + 用户信息（上传/下载量、分享率、魔力、等级）。
- 种子搜索（无限滚动）、分类筛选。
- 种子卡片：**促销标签（免费/2x免费/50%/2x上传 + 剩余免费倒计时）**、名称、大小、做种/下载/完成数、标签。
- **一键发送下载器**（选目标下载器 + 立即开始/暂停添加）。
- **视频详情页 → PT 搜索一键跳转（带年份）**。

#### 5.6.4 媒体管理（NASTool / MoviePilot）
- 仪表盘、订阅、下载、搜索、媒体库整理、站点、高级、设置（NASTool 多分类）。
- 订阅→自动下载→自动整理入库。

#### 5.6.5 追踪（Trakt）
- 设备码授权，待看/在看/已看/评分同步，播放完成上报。

#### 主要页面
**传输管理页（下载/上传/缓存三 Tab）**、**下载器详情页**、**发送到下载器弹层**、**PT 站列表 + 详情/搜索页**、**NASTool 主页（多分类导航）**、**Trakt 连接/列表页**。

#### 跨模块联动
这一整块就是为了支撑 §6.1 的招牌链路。设计要让"一个种子如何变成可播放的媒体"全程可追踪。

## 6. 标志性跨模块流程（端到端）

> 这些"链路"是产品价值的集中体现，设计时应作为**重点叙事场景**来打磨，保证每一步衔接顺滑、状态可见、可回退。

### 6.1 ⭐ 招牌链路：找资源 → 下载 → 入库 → 播放
```
影视详情页 / 推荐项
   └─[一键 PT 搜索（自动带"标题 + 年份"）]→ PT 站搜索结果
        └─[选种子 · 看促销标签]→ 发送到下载器弹层（选下载器 + 立即/暂停添加）
             └─→ 下载器开始下载（进度可见、可暂停/继续/取消）
                  └─[下载完成]→ 媒体管理自动整理入库（或手动归位）
                       └─→ 影视库扫描 + 刮削（边扫边显）
                            └─→ 新资源出现在影视库
                                 └─[播放]→ 播放器（自动配字幕 + 恢复进度 + 完成上报 Trakt）
```
设计要点：用户在链路任意环节都应能"看到它进行到哪了"。理想状态有一个贯穿的"任务/资源状态"可追踪（从种子→下载中→整理中→已入库→可播放）。

### 6.2 续看 / 多端接力
- 任一端播放 → 进度本地保存 + 上报媒体服务器/Trakt + WebDAV 同步 → 其它端"继续观看"出现该条目 → 续看。
- 音乐：正在听 → 切到车机/桌面/TV 继续。

### 6.3 文件 → 智能识别 → 对应消费
文件浏览器点任意文件 → 按类型进入视频播放器 / 音乐播放 / 图片查看器 / 电子书 / 漫画阅读器。

### 6.4 在线书源 → 搜索 → 缓存入库
导入 Legado 书源 → 跨源在线搜索（流式聚合）→ 选书加入书架 → 在线阅读并缓存章节 → 离线可读。

### 6.5 照片 → 人脸聚合 → 人物相册
相册扫描 → 人脸检测/聚类 → 人物页 → 点人物头像 → 该人物所有照片。

### 6.6 字幕全链路
播放无字幕 → 在线搜索下载（OpenSubtitles）或选内嵌轨 → 不懂的语言一键 **AI 翻译**为目标语言 → 调样式/延迟 → 投屏时字幕随行。

## 7. 分平台体验要点

> 一套设计语言，按形态落地。以下是每个形态"必须照顾到"的事，视觉与交互细节仍由设计师定。

### 7.1 手机（iOS / Android）
- 单手可达、底部为主操作区；竖屏为默认，播放器/漫画/视频支持横屏。
- 详情/播放/阅读进入时隐藏底部导航，沉浸。
- 手势丰富：视频手势（进度/亮度/音量/双击）、迷你播放器上滑展开、列表长按多选。
- 系统集成：锁屏控制、Now Playing、安卓灵动岛/通知媒体控制。
- iOS 可选液态玻璃风格（原生模糊 + 原生 TabBar）。

### 7.2 平板
- 横屏双栏（列表 + 详情 / 树 + 内容 / 库 + 预览）。
- 漫画双页、电子书更大版面是平板主场。
- 可承接更高信息密度，但仍是触摸优先。

### 7.3 桌面（Windows / macOS / Linux）
- 侧边导航 Rail（宽屏展开文字）；"我的"master-detail。
- 信息密度更高（更紧凑的行高/内边距）、右键菜单、拖拽、键盘快捷键（切 Tab、搜索、Esc 返回、播放控制）。
- **管理重场景**：批量刮削、去重、下载器管理、文件批操作、连接源管理。
- 桌面歌词独立悬浮窗。
- 多窗口/窗口状态记忆。
- 平台特性：Windows Jump List、macOS Spotlight 索引/菜单栏。

### 7.4 ⭐ TV（10 英尺体验，全新形态——重点设计）

> 目前没有任何 TV 专属实现。这是本次设计的**重大新增**。请把它当作一个"为客厅、为遥控器、为 3 米外"重新设计的消费型 App，而不是把手机界面放大。

#### 设计前提
- **输入是遥控器 D-pad（上下左右 + 确认 + 返回）+ 可选语音**，没有指针、没有精细触摸。
- **焦点（Focus）是一等公民**：任何可操作元素被选中时必须有清晰、醒目的焦点态（放大/高亮/投影/边框，设计师定形式，但"看一眼就知道焦点在哪"是硬要求）。
- **层级要浅**：用户不该在 TV 上钻很多层。首页 → 详情 → 播放，尽量三层内。
- **大字、大图、留白**：远距离可读；海报和封面是主角。
- **少文字输入**：搜索尽量用语音/推荐替代键盘；必须输入时用大号网格键盘或配套手机输入。

#### TV 端保留哪些功能
| 保留（消费） | 弱化/移除（管理） |
|---|---|
| 影视：继续观看、推荐、媒体库浏览、详情、播放、字幕、投影 | 刮削、去重、PT、下载器、文件管理、连接源添加 |
| 音乐：曲库浏览、播放、歌词（大屏歌词很适合） | 音乐刮削、统计、回收站 |
| 相册：浏览、幻灯片、（人物浏览可选） | 去重、人脸训练 |
| 漫画：可作为阅读消费 | 书籍/笔记弱化 |
| 选择"已连接的源"、切换账号 | 新增源的复杂表单（引导去手机/桌面完成） |

#### TV 首页建议结构（参考，可重做）
- 顶部/侧边大焦点导航（影视 / 音乐 / 相册 / 设置）。
- 主区为多条**横向 Rail**：继续观看 → 每日推荐/Hero → 最近添加 → 各媒体库 → 系列合集。
- 选中海报时背景大图/简介浮现（"沉浸式详情预览"）。

#### TV 播放器
- 简化控制：进度条 + 播放/暂停 + 快进退 + 字幕/音轨/清晰度 + 下一集；遥控器左右键 seek、上下键调出菜单。
- 字幕/音轨/清晰度用大列表选择。
- 自动下一集、片头片尾跳过（如有）在 TV 上价值高。

#### TV 端的"管理缺口"如何补
- 凡是 TV 上不做的管理动作，给出"请在手机/桌面端完成，或扫码用手机配置"的引导。
- 可考虑"手机当遥控器/输入法"的协同（设计可探索，非强制）。

### 7.5 车载（CarPlay / Android Auto）
- **只做音频**：浏览（专辑/艺人/歌单/最近/电台）+ 播放控制，模板化、强约束。
- 安全第一：大按钮、少层级、语音优先、禁止复杂视觉。
- 与手机端播放状态接力。

### 7.6 系统级集成界面（跨平台延伸）
| 集成 | 平台 | 内容 |
|---|---|---|
| 锁屏 / Now Playing | iOS/Android | 封面、标题、播放控制、进度 |
| 灵动岛 / 实时活动 | iOS（安卓类似悬浮） | 当前播放的紧凑/展开态 |
| Media Widget / 桌面小组件 | macOS / iOS | 当前播放、快捷控制 |
| 桌面歌词悬浮窗 | Windows/macOS/Linux | 滚动/卡拉OK歌词、可拖动、样式可调 |
| CarPlay / Android Auto | 车机 | 见 §7.5 |
| Jump List / Spotlight | Windows / macOS | 快捷入口、索引 |
| 系统通知 | 全平台 | 长任务完成提醒 |

> 这些界面受系统模板约束较强，设计师在"系统允许的范围内"发挥；但应与 App 主视觉保持一致的气质。

## 8. 全局状态、空态与边界情况

设计要为每个列表/详情/播放器统一对待这些状态（视觉自由，但都要有）：

| 状态 | 何时出现 | 设计要点 |
|---|---|---|
| **首次无源** | 全新安装、没连任何源 | 友好引导：解释"自带数据源"理念 + 一键添加 + 可跳过先逛 |
| **加载 / 骨架** | 列表/详情拉取中 | 骨架屏优先于转圈，避免布局跳动 |
| **空态** | 库为空、搜索无结果、无字幕、无歌词、无书签 | 给出"为什么空 + 下一步动作" |
| **错误** | 网络/权限/格式/连接失败 | 明确原因 + 重试 + 备选（如转码/换源） |
| **离线** | 源不可达 | 显示缓存内容 + 离线标记 |
| **长任务进行中** | 刮削/下载/上传/同步/人脸扫描/转码/翻译 | 进度 + 可中断 + 全局可见 |
| **需升级（会员）** | 功能超出当前等级 | 锁定占位 + 升级引导（不要直接消失） |
| **需二次验证** | 群晖等 | 引导输入 OTP |
| **大列表** | 海量文件/媒体 | 虚拟化 + 渐进/分页加载 + 预缓存关键图 |

## 9. 设计自由度边界（必读）

为了让设计师"放开手脚但不破坏功能"，明确三类边界：

### 9.1 必须保留（否则功能不成立）——这些是"约束"
1. **七大功能域的能力都要有落点**（影视/音乐/相册/阅读/传输下载/连接源/我的），但**导航形态、命名、分组、是否合并完全自由**。
2. **"多源并存 + 源能力差异"必须可表达**：用户能看到/切换/筛选不同源，并理解某源能干什么（§4.1）。
3. **招牌链路必须顺滑可追踪**（§6.1）：从 PT 搜索到可播放，每一步状态可见。
4. **专业播放/阅读能力的入口都要在**：字幕（含 AI 翻译）、多音轨、清晰度/转码、投屏、倍速、手势；阅读的排版/主题/翻页/TTS；漫画的模式/方向/缩放。具体怎么摆是你的事。
5. **长任务都要有进度与可中断**（下载/刮削/同步/人脸/转码/翻译）。
6. **焦点态（TV）/ 触摸目标（移动）/ 信息密度（桌面）的可用性底线**：TV 焦点必须明显；移动触摸目标足够大；桌面可更密。
7. **会员等级标识与功能锁定的一致性**。
8. **安全与隐私**：应用锁解锁页、切换器遮蔽必须存在。
9. **系统集成界面**在各平台都要有对应（锁屏/Now Playing/桌面歌词/车载等）。

### 9.2 完全自由（鼓励大胆重做）
- 整体视觉语言、品牌气质、配色、字体、图标、插画、动效、音效。
- 是否保留/重做"Classic vs 玻璃"双风格，或提出全新风格系统。
- 所有页面的布局、信息层级、卡片样式、列表/网格形态。
- 导航的具体形态（底栏/侧栏/抽屉/胶囊/磁贴…）与命名。
- 手势、快捷键、右键菜单的具体设计。
- 详情页、播放器、阅读器、刮削流程的交互重构。
- 空态/错误/引导的表达方式。
- TV / 车载的整套界面（在 §7.4/§7.5 约束内自由发挥）。

### 9.3 建议探索方向（加分项，非要求）
- **统一的"全局聚合搜索"**：一个搜索框横跨所有媒体类型 + 在线源。
- **统一"任务中心"**：把下载/上传/刮削/同步/人脸/转码集中可视化管理。
- **更强的"资源状态追踪"**：让招牌链路像快递一样可追踪。
- **跨端接力的显式化**："在另一台设备继续"。
- **TV × 手机协同**：手机当输入法/遥控器/投送源。
- **首启引导的减负**：让没有 NAS 知识的家庭成员也能上手。
- **六大媒体类型一致的"卡片→详情→消费"心智模型**，同时让每类有自己的性格。
